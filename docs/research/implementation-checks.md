# 实现与验证概览

本文维护当前实现的证据范围与限制，不作为逐次调试记录或部署清单。测试命令和手动步骤见 [部署与验收](../testing.md)，逐项标准见 [交付审计](acceptance-audit.md)。

## 证据分类

| 类别 | 可以证明 | 不代表 |
| --- | --- | --- |
| 静态约束 | API、类型、SQL、配置和权限边界的当前实现 | 任意真实部署都满足这些条件 |
| 自动行为测试 | 模拟协议与平台响应下的配对、导航、输入、投递、恢复、格式和隔离规则 | 实际平台、所有网络故障和版本差异已验收 |
| 隔离原生测试 | 临时服务与模拟模型中的共享 active turn、steer、断线继续和历史读取 | 已有 Desktop 进程可以被第二客户端附加 |
| 授权集成验证 | 受测共享实例、SSH 跳转、TOTP、平台账号能力和会话流程可运行 | 其他实例自动获得控制资格或全部场景通过 |
| 手工客户端验收 | 被实际操作的客户端呈现与交互 | 所有客户端版本和后续平台行为不变 |

## 重点验证规则

- 观察、菜单、状态与历史不发起原生执行或生命周期操作；最后桥接客户端退出不终止已运行任务。
- 原生请求保留会话执行策略；活跃 turn 的追加带明确 expectedTurnId，冲突不自动开启新轮。
- 输入和投递持久去重；未知写入、创建、发送或删除结果不自动重试。
- 平台身份、执行实例、thread、工作区和容器隔离；撤销权限和配置变化在执行/投递前复核。
- 历史按 turn 和 item 归属，区分中间过程、最终结果及错误；外部输入可见，Telegram 自身输入不重复展示。
- 附件展示保留正文和文件名，不读取或预览图片；渲染保护代码、转义、链接和 HTML 安全。
- 多目录分页、目录发现与排序不扩大允许范围；后台不覆盖显式移除和自定义配置。
- SSH 挑战只回答已配置的类型；TOTP 使用成熟实现、窗口去重和尝试限制，认证信息不写入日志或公开资料。
- 同一私聊各 topics 共享限速；批次、typing、状态图标和删除操作遵守各自的恢复边界。

当前开发检查包括 workspace 测试、全 target Clippy、rustfmt 及默认包含三端的 release 构建。测试数量和构建大小随版本变化，不在本文追加每次运行的流水记录。

## 尚未完整证明的范围

- 没有共享入口的本地 Desktop 活跃实例不能直接接入；共用历史目录不足以绕过这一限制。
- 审批、结构化问答、跨客户端竞争、慢网络、磁盘故障和长时间离线的全部组合尚未完成真实验收。
- 原生未持久化且桥接未收到的临时消息或错误通知无法恢复；不承诺完整的 delta 连续性。
- Telegram 无法列出任意 topics，删除同步受平台能力限制；消息投递未知时不承诺 exactly-once。
- Discord/Slack 保持原型范围；Claude 与 Lark 是规划，不能作为现有能力宣传。

具体条件以 [验收审计](acceptance-audit.md) 和 [接入限制](../design/local-desktop.md) 为准。构建支持与体积评估方法见 [构建说明](../build.md)。
