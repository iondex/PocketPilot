# Telegram topics：行为与平台边界

本文解释可复用的交互规则和平台限制。详细设计见 [Telegram](../design/telegram.md)，操作步骤见 [部署与验收](../testing.md)。

## 管理入口与消息归属

- bot 需要启用私聊 Topics。建议在 BotFather 关闭用户自行创建话题，避免客户端入口行为与应用会话管理混淆。
- 每个配对私聊有固定管理 topic，仅处理导航、配置范围内的目录管理及确认；普通任务文本不会发给 agent。
- 一个 session topic 对应一个原生 thread。topic 外操作路由到管理上下文并给出提示，不能暗中发送到最近使用的会话。
- Bot API 无法移动用户已发送的消息或强制切换客户端页面；路由处理与客户端显示是不同能力。
- 同一原生会话的外部用户输入以 🧑‍💻 展示；Telegram 自身输入通过持久 client ID 去重，不按文本相同猜测来源。

## 菜单、目录与状态

管理界面使用内联按钮，在同一条消息中编辑切页；/start 提供新的可见入口，明确的菜单编辑失败会补发。旧按钮恢复当前页面，不以过期错误打断正常浏览。选择绑定稳定 ID，权限范围变化时重新确认；显示设置、速率和活动时间变化不使只读浏览失效。创建和删除确认受当前页面、投递回执、恢复标记和新鲜度约束，过期时重新确认。

工作区来自应用 catalog 和允许实例的会话目录元数据，不等于服务器目录列表；新目录可手动登记。列表完整分页，工作区按所属会话最大更新时间倒序，会话汇总登记目录后整体排序。会话翻页使用固定快照，主动重新打开列表读取新活动。

`/new` 依次选择主机、工作区、标题并确认，创建空会话；标题不作为任务发送。同名工作区需明确主机或完整 ID。topic 标题只保留截短原始名称，详情通过 `/status` 查看。

管理 topic 的 icon 为 📁；会话 icon 根据运行状态更新，标题不重复添加状态文字或 emoji。只在变化时投递并合并限速，不用于动画。运行中使用独立 typing lease；等待、离线或空闲时停止续期。平台可能为元数据更新产生服务提示。

## 正文、历史与错误

正文以同行 emoji 区分阶段：💭 中间文本、✅ 明确 final、💬 阶段未知、❌ 失败、⚠️ Codex 重试；工具与推理不转发。正常输入不额外发送成功 ACK，短时输出合并并受私聊共享预算限制。

`/history` 动态读取最新用户输入及其后同轮最终结果和错误；没有最终结果时不配旧答案。较早轮次的错误通过 `/history errors` 独立查询。已观察错误按实例与 thread 留存，原生未持久化且桥接未收到的通知无法补回。连接故障提示去重，历史暂不可读不等于原生任务停止。

Markdown 使用 GFM 解析后转换为安全 HTML，保护代码、转义和链接；窄表等宽展示，宽表或富文本表转为逐项内容。进入会话只显示有长度上限的最近预览，不自动发送历史文件；再次打开已绑定会话不重复投递。/history 主动查看上轮结果，长结果分段显示，不提供完整历史导出。原生附件包装只在展示时清理为正文和文件名，不显示绝对路径或图片；Telegram 支持文件或图片与可选说明一起发送到绑定 session；纯文件也可提交，详见 [附件说明](../attachments.md)。

## 删除与同步

Bot API 不提供完整 topics 列表、单个 topic 读取或可靠的删除更新。因此 `/topics` 只管理本程序记录的话题；明确不存在时清理本地映射，超时、限流或关闭状态不能当作删除。

单项删除与 `/topics clear` 均需确认。批量确认固定 ID 范围，保留管理入口和确认后新建的话题。操作只影响 Telegram 话题、聊天记录及本地关联，原生会话仍存在。未知结果时暂停对应投递，不自动重删；用户复核后可发起新确认。

## 命令与生命周期

Telegram 私聊共享一套命令菜单，无法按 topic 注册不同列表；`/help` 按实际上下文解释命令。管理、状态、历史、删除及连接恢复都不停止原生任务；观察不 resume，原生续轮和 steer 只来自明确用户输入。

平台接口来源见 [设计文档](../design/telegram.md)。实际客户端呈现与未覆盖平台行为仍需部署者验证。
