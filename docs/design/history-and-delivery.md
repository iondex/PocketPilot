# 会话预览、历史与消息投递

## 1. 进入会话

Telegram 入场使用最近内容预览，不提供完整历史导出。

| 场景 | 展示规则 |
| --- | --- |
| 首次绑定空闲会话 | 最近输入及同轮最终结果或错误的短预览 |
| 首次绑定运行中会话 | 最近输入及本轮最终结果或最新进展的短预览 |
| 再次打开已绑定会话 | 复用 topic 和观察游标，不重复投递旧历史，不跳过未投递的新内容 |
| 新建空会话 | 不发空历史或占位回复，等待用户首条任务 |
| 重启或网络恢复 | 核对状态和历史增量，不自动发送全历史 |

预览预算由 `delivery.history_preview_chars` 控制，默认 1200，允许 256–2800。按 Unicode 边界和转义后的消息长度保守计量，为操作提示留出平台长度余量。短内容保留 Markdown；超长内容转换为安全的纯文本摘录并标明省略。预览是已读取内容的摘录，不向 agent 发送总结请求。

入场不自动生成 Markdown 文件。只读历史读取用于选取最近上下文和建立去重基线；已被预览省略的旧内容仍保留在原生服务，可主动查询。历史未完整读取时不将已读片段冒充最近记录。

Telegram 自身已发送的输入通过 client ID 去重；同一原生会话的外部输入以 🧑‍💻 展示。其他阶段使用 💭 中间过程、✅ 明确 final、💬 未知阶段、❌ 最终失败，emoji 与首行同行。

可恢复的错误通知（`willRetry=true`，包括 Reconnecting/重试进度）不进入消息或历史展示。只有不再重试的错误通知、原生 failed/interrupted 结果作为错误展示；旧账本中的 error_retry 记录也不重新投递。普通 commentary/partial answer/plan 与最终回答按原有规则继续展示。后台连接或历史读取故障只记录日志、更新可知的状态图标，不发送错误气泡；用户主动命令无法完成时仍返回对应的失败回执。

## 2. 主动历史查询

| 命令 | 语义 |
| --- | --- |
| `/history` | 动态读取最后一次用户输入，及其后同轮已确认 final 与错误；不含中间过程 |
| `/history errors` | 独立查看近期错误及其 turn 归属，不将旧错误配到新输入 |

同轮存在多次 steer 时，从最后一次用户输入之后选择结果。该输入尚无 final 时不使用更早的答案；phase 缺失时不将最后一条 commentary 猜成最终结果。

只读历史读取只用于最近交互、状态与增量去重；完整记录在原客户端查看。附件上下文展示为用户正文与文件名，不自动回显私有路径。

## 3. 平台长度与格式

入场预览保持在单条文本预算内；普通长输出及主动查询的长结果均按文档结构分段发送。公共解析保留强调、链接、引用、列表和代码；每段独立渲染，不能保真的语法保留为字面文本，不生成历史附件。

Telegram 使用类型化 RichMessage blocks，Slack 使用 rich_text/header/table，Discord 使用 Components V2 Text Display 输出支持的 Markdown 子集。转义、链接协议和通知保护由公共结构与平台适配共同保证。未知网络结果不自动另发一份，超出处理预算明确报错。

分段结果在发送前固定并持久化，每段成功回执后记录段号，恢复不重发已确认前缀。Telegram 的可合并批次开始分段后冻结，后续内容进入新批次，避免追加内容被旧分段缓存覆盖。

## 4. 观察、游标与消息合并

历史 item 以 turn/item 身份去重，内容和 phase 变化可产生新输出；运行完成标志变化不重发已经展示的中间文本。升级兼容既有游标，不因内部表示变化重播历史。

首次预览与观察基线在同一事务中提交。后续只处理未覆盖的内容变化；再次打开已有绑定保留原游标和版本，不把尚待发送的增量误当作旧历史丢弃。原生历史不是原子快照，无法证明连续性时不承诺完整的 delta 覆盖。

连续可见输出可进入同一持久批次。配置包含短时窗口、消息阈值与固定最长等待时间；持续生成也不能无限延后。批次不跨会话、topic、权限范围或绑定版本，不合并用户输入命令，不改变原生 turn/steer 顺序。

同一私聊的所有 topics 共享速率预算，并尊重平台 retry_after。每个消息分段也占投递预算。平台积压只影响消息投递，不停止原生任务。

## 5. 持久化与恢复

应用只维护自身的绑定、操作、观察和投递状态，不直接改写 Codex 数据库。观察游标与待发送内容原子提交；发送回执保留平台消息 ID、状态及绑定版本。已观察错误按实例/thread 有界留存，供重启后的显式查询。

每次执行和投递前重新检查指定用户、配置范围和绑定身份。撤销或移除后未开始的工作不得继续；已被原生接受的请求不能撤回。平台发送、原生写入或资源创建结果未知时保留不确定状态，不自动重放。

退出、崩溃和重连只回收桥接连接，不停止或重建原生会话。最近交互查询只读，审批继续由原客户端处理。平台之外的历史展示差异见各 adapter 设计；Discord 原型不由 Telegram 的预览规则推断为已完成同等体验。
