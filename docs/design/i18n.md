# 共享语言资源与错误展示

`i18n` crate 是所有 crate 共用的文案与错误展示依赖。中英文资源只保存在 `crates/i18n/locales/`，由 rust-i18n 编译进程序；不读取环境变量，不调用全局 `set_locale`。

翻译键为稳定 ASCII ID，例如 `tg.history.user`、`nav.workspaces`、`error.ssh.timeout`。文案修改不改变 ID。中英文 key 集合和插值参数必须一致，测试同时检查源码引用的 ID 存在。不要以中文或英文原文作为查找键。

`text(locale, id)` 读取文案；`t!(id, locale = ..., name = ...)` 复用 rust-i18n 的单次插值，不把用户参数再当模板解释。每次调用都显式传入语言，所以不同用户可以并发使用不同语言。

根 TOML 的 `language = "zh-CN"` 控制 CLI 和后台展示的缺省语言，也支持 `en`。Telegram 继续由 `telegram.default_locale` 与用户 `/language` 偏好决定，用户偏好优先。Discord 的命令交互采用客户端语言，后台采用根配置语言。CLI 自身输出和业务错误可翻译；Clap 生成的帮助与参数用法文本保持上游格式。

各 crate 的错误枚举实现 `LocalizedError`，返回包含稳定 ID 与安全参数的 `Message`。透明包装错误继续委托给底层类型，保留协议错误码、重试秒数等信息；不先格式化为字符串再反向猜测翻译。`Display` 保留稳定诊断，最终在 Telegram、Discord 和 CLI 边界用目标语言展示。日志不依赖当前用户语言，也不包含 token、TOTP seed、验证码、消息正文或原始服务响应。

Telegram 菜单使用 `UiText::Message` 与 `UiText::Literal` 区分文案 ID 和用户数据；出站提示显式用 `Outbound::ui`，原文用 `Outbound::text`，agent Markdown 用 `Outbound::agent`。不能对任意正文再做一次翻译查找。名称、路径、标题和任务结果即使碰巧等于某个翻译 ID，也必须原样保留。

旧导航中的字符串按字面值读取，刷新后产生带 ID 的新菜单，不需要数据库 migration。语言偏好仍保存在应用自身的状态库中。会话、原生标题和运行状态不会因为语言切换而改变。
